# Record: MI25 re-benchmark on llama.cpp 11193 — 2026-09-25

## Outcome

Re-measured the MI25 (Vulkan, RADV VEGA10) on the upgraded llama.cpp build and compared against the `records/2026-09-21-01-mi25-inference-benchmarks.md` baseline, which was taken on 0.4.0-dev build 10893.

Build 11193 is safe to keep: no resident model regressed, and gemma-12B prefill at full offload improved by about 45%.
A new `ngl` sweep on Qwen3.8-Flash-Next shows that partial offload is strictly worse at every step, which is stronger evidence than the two endpoints the earlier record measured.

The gemma-12B full-offload prefill gain is the only material change.

Generation is unchanged for both models.
The gemma-12B `ngl 0` figures are the least trustworthy cells in the table; the caveats below explain why.

## Qwen3.8-Flash-Next partial-offload sweep

`batiai/Qwen3.8-Flash-Next-GGUF:Q4_K_M`, reported as `qwen4exp A3B Q4_K - Medium`, 110.96 GiB, 176.94 B params.
The earlier record measured only `ngl 0` and `ngl 99`.

| `ngl` | Prefill (pp256) | Generation (tg32) |
| ---- | ---- | ---- |
| 0 | 12.74 | **4.84** |
| 8 | 6.57 | 3.07 |
| 16 | 7.01 | 1.89 |
| 32 | 8.52 | 0.97 |
| 99 | 13.34 | 0.65 |

Generation falls monotonically with offload depth, and prefill collapses as soon as any layer moves to the GPU.
The working set cannot fit in 15.98 GiB, so every offloaded layer adds PCIe traffic without reducing the bytes that must still be read from system RAM.
Partial offload is therefore not a middle path for this model.

## Supporting facts (verified 2026-09-25)

- MI25 total VRAM is 17,163,091,968 bytes (15.98 GiB), unchanged.
- The router loads models on demand per request, one child server per model id; it holds no weights itself.
  A request naming an unknown model returns `HTTP 400 model '<id>' not found` rather than falling back to a default.
- `rocm-smi` reported about 8.4 GB of VRAM as used while no model was loaded.
  This is recorded as an observation, not a finding: no leak is claimed, and the accounting is not explained.

## Caveats

- The 10893 baseline could not be re-run.
  The matching `llama-bench` front-end was overwritten by the upgrade; only the 0.4.0 libraries survive in `/usr/local/lib`.
  A controlled A/B would require repointing the versioned library symlinks for live services, which was judged not worth the risk.
  "Change" in this record therefore means *11193 measured against numbers recorded on 2026-09-21*, not a single experiment.
- The baseline numbers may have been taken with a contaminated GPU.
  At the time of the 2026-09-21 run, gemma-12b was resident from an unrelated check, holding roughly 10 GB of VRAM.
  If that is what happened, the baseline is understated, the true gemma-12B `ngl 99` gain is smaller than 45%, and the `ngl 0` comparison is unreliable.
  This is the reason to distrust the one negative figure in the resident-model table.
- Measurements use `-r 1`, so per-configuration variance is narrower than the between-run variance implied by the gemma-12B `ngl 99` repeats.
  Treat single-digit deltas as noise.

## Decisions

- Keep build 11193 on both hosts; no regression was found on resident models and gemma-12B prefill improved.
- Keep `qwen38` at `ngl = 0` if it is kept at all, and do not attempt partial offload on the MI25. The sweep shows offload helps at no depth.
- Leave the 2026-09-21 record unchanged. It remains the 10893 baseline, and this record supersedes only its currency, not its content.
